# Zero-budget deployment (₹0 target)

This guide describes a free-tier demo deployment. It is not a promise of production uptime, permanent free hosting, or complete independence from infrastructure providers.

## Components

| Component | Candidate | Notes |
|---|---|---|
| Source and CI | GitHub | Free allowances apply |
| Remote MCP server | Render Free Web Service | Sleeps when idle and cold-starts; no production SLA |
| PostgreSQL | Neon Free | Compute, storage, and network quotas apply |
| AI reasoning | Existing ChatGPT account | ORBIT core does not call a separate paid model API |

The hosting providers are external infrastructure dependencies. If "no third-party services" is an absolute requirement, ORBIT must be self-hosted on infrastructure you control; that cannot also be guaranteed free, always-on, and managed for you.

## Before deployment

1. Create a Neon project on its free tier.
2. Copy the PostgreSQL connection string from Neon. Keep it private; do not paste it into GitHub, issues, or chat.
3. Review the Render Blueprint plan in the Render dashboard.
4. Approve only after checking the service name, plan, and environment variables. The blueprint is configured for a free web service and does not intentionally modify unrelated services.
5. Set `DATABASE_URL` directly in the Render service's Environment page. Do not expose the value in source control or chat.
6. Ensure `ORBIT_API_TOKEN` is a strong secret generated by the hosting platform.
7. Deploy and apply the database migrations using the repository's migration command or a controlled release step.

## Runtime checks

- `GET /health` should return HTTP 200 and report `database: connected`.
- The MCP endpoint is `/mcp`.
- Test MCP initialization and tool discovery with a compatible MCP client.
- Run read-only tests first; use disposable records for write tests.
- Confirm database persistence after a restart.

A successful build does not establish that the database, MCP transport, authentication, or ChatGPT integration works end to end.

## Current security limitations

- ORBIT currently uses a single-owner bearer token and a configured default user ID.
- OAuth 2.1 and per-user tenant isolation are not implemented.
- Do not distribute the same token to multiple users or market this release as a public multi-user SaaS.
- Review the SSRF and outbound request protections before exposing Dev tools to untrusted users.

## ChatGPT compatibility

A hosted ORBIT endpoint does not grant custom MCP access to every ChatGPT plan. Confirm the current account's custom MCP and write-action support before deploying. See [ChatGPT connection requirements](CHATGPT-SETUP.md).

## Local development is optional

The local PostgreSQL and Docker workflows are for contributors. They are not required for end users of a hosted ChatGPT-connected ORBIT instance. The owner can manage deployment and database credentials through the hosting dashboards without asking end users to install PostgreSQL or use a terminal.

## ₹0 caveats

Free plans can change, sleep, suspend services, or enforce quotas. Do not add a payment method if zero spend is mandatory. If a provider requires payment or a card for the required capability, stop and choose another option rather than silently incurring a charge.
